# Cars24 Patch — project instructions

@BRAND-GUIDE.md

## Always (the short version — details are in the guide above)

- **The message:** India has swerved, slowed down and suffered enough, **so we're fixing the potholes ourselves.** Never accountability, blame or "who owns this road"; say who fixes it (us). The sign-up button is `tell me first ↗` and always promises *we'll email you the day we start fixing.* Write for the Gen Z reader in BRAND-GUIDE §3 (first line carries the idea, one joke per block, long stuff folded, every ask says what you get).
- This site is **intentionally loud, funny, Gen Z and rebellious**. Never "normalise" it into a clean corporate/SaaS look. Copy the existing pages' style.
- **Copy benchmark = the homepage hero and the wall page:** quirky, human, one odd specific thing per block, one Gen Z touch at most. Copy that describes the page, lists three things or summarises reads as AI-written and has been rewritten twice; see BRAND-GUIDE §3 "Benchmark". Rewriting never adds facts.
- Voice: deadpan, lowercase source copy (CSS uppercases headlines), short fragments, **no exclamation marks**, no invented facts. Serious data stays straight and sourced. No jokes about the deaths.
- Brand name is **Cars24 Patch**, tagline **a Cars24 Rebellion** (pre-footer band + footer only — not hero, not navbar).
- **Stack:** Next.js 16 App Router + React 19 + TypeScript, no Tailwind. `npm install`, `npm run dev` (http://localhost:3000), `npm run build`. The repo is the source of truth; the old local files (`index-genz.html`, `index-genz-meme.html`, `404-genz.html`, `index-cfi*.html`) are retired.
- **Build everything in Next.js** (user, 2026-11-12): no new pages or features in `public/*.html`; the remaining HTML pages get ported one by one and deleted.
- **Where things live:** homepage `/` = `app/page.tsx` + `components/home/*` (CSS `app/globals.css`, behaviour `lib/home-behaviour.js`, which finds elements by id/class, so keep them in sync). 404 = `app/not-found.tsx`. The wall = `app/wall-of-holes/` (ported 2026-11-12). Case files = `app/case-files/` (ported 2026-11-15). The diary = `app/updates/` and research = `app/research/` (both ported 2026-11-18). Shared pieces for ported pages: `components/site/` (`SiteNav` with `PageLink` + `PORTED`, `PageFooter`, `PageEffects`, `Photo`, `hub.css`, `HubFilters`, `HashLinks`). Still HTML in `public/`: `lab.html`, `dodge.html`, `rishta.html`, `on-the-move.html`, `know-who.html`, served by `STATIC_PAGES` in `next.config.ts`. Porting a page = move it to `app/<route>/`, delete its `public/` file, move its name from `STATIC_PAGES` to `PORTED` in `next.config.ts`, add its route to `PORTED` in `SiteNav.tsx`, and pass the DOM + pixel parity check (BRAND-GUIDE §8).
- **No reloads between ported pages:** links go through `PageLink` (Next `<Link>`), so every page effect must clean up after itself (listeners, timers, loops, observers, classes on `<html>`). In-page `#` links are routed by `HashLinks` (in the layout): write `<a href="#id">`, never set `location.hash` in code. See BRAND-GUIDE §9.
- **Lab first:** every experiment goes live in **the lab first** (front page `public/lab.html` at `/lab`, plus the lab pages). Only after a final check and the user's confirmation is anything promoted to the homepage. Never edit the homepage first. Anything big gets its own lab page and the lab front page keeps a card for it.
- **Navs:** ported pages use `components/site/SiteNav.tsx`. In the HTML pages (`lab`, `dodge`, `rishta`) the three `LAB-NAV` blocks are identical (lab bar + six links). **The four hub pages (research, the diary, case files, the wall; all Next.js now) never link to `/lab`, `/dodge` or `/rishta`.** Links between pages use `a[data-page]`, never hard-coded paths. A new lab page also goes into `STATIC_PAGES`. See BRAND-GUIDE §12.5.
- **The homepage CSS is global.** A class name reused on another Next page picks up the homepage rule (this broke the 404 twice). Prefix page-only classes and pixel-diff.
- **The lab is a hub that grows** (BRAND-GUIDE §12.6): an event goes on the diary (`app/updates/`), a lesson in case files (`app/case-files/`), the evidence itself on research (`app/research/`). **Publishing red lines:** never put names or contact details of officials, scientists or companies, allegations, vendor criticism by name, costs or quotes, deal terms, unreleased tech, the pilot city or timeline, or internal chatter on the public site. What a source told us in a meeting is "told to us, not tested by us", in generic terms. Scan every public page for these before any push.
- **Do not push to GitHub unless the user says "push" or "go".** Push a branch first and check its Vercel preview; `main` deploys to production within a minute. Never force-push `main`. Do exactly what was asked, nothing more.
- Before adding a CSS class, id or variable name, **grep the whole repo first** (the homepage owns `.cf` = confetti; two variables both named `sr` once broke screen-reader announcements).
- Every change must pass the responsive audit (280–2560px, both themes, no horizontal scroll, nothing clipped) and `npm run build` before you call it done.
- Never commit the real Google Sheet ID (`google-apps-script.gs` keeps a placeholder). Intercept `script.google.com` when testing sign-ups.
- Never scrape or repost images from Google Images / social media. Ask before downloading any file.
- When a decision changes, update `BRAND-GUIDE.md` in the same commit.
